2三条关键路径 性能架构的核心：大内容走原生通道，JS 桥只过元数据

A · 大文件快路径（预览 / 封面 / 索引）

preview.js 请求打开→ solace.getDocUrl(id)→ https://localhost/_capacitor_file_…/files/<id>.pdf→ WebViewLocalServer 原生拦截→ FileInputStream 流式返回→ pdf.js 在 worker 里 fetch＋解析
为什么：桥传 base64 需两侧全尺寸编解码＋JSON 序列化＋JNI 拷贝，实测纯 JS 编码 10MB≈1.1s （原生 SHA-256 同量仅 29ms，差 37 倍）——0.2.x 的卡顿全部源于此。封面 getCoverUrl 同一条路； 不支持 Range → pdf.js 自动整取仍全速（30.8MB≈220ms）。预览打开期间封面/索引队列 sleep 让路。

B · 导入管线（SAF 多选）

pickPdfs() SAF 选择器→ copyAndHash：一次读取同时做 SHA-256＋复制（哈希与副本严格同源）→ importVia：SHA-256 查重→ 原子 rename 暂存→files/<uuid>.pdf→ mutationQ 落库 library.json
兜底链：原生选择器异常 → WebView <input type=file> 的 JS 字节路径（慢但不失效）； 一次读取消除「先哈希后复制」之间文件仍被写入的竞态；失败原生侧自动清半截文件。Olib 下载目录的自动入库复用同管线（内容去重）。

C · 手写标注（墨迹层事件流）

preview.js 派发 solace-ink-layout（坐标系基准）→ 三层画布：pdf.js 页面 ＋ 已提交墨迹 ＋ 当前笔画→ 1.5s 防抖保存 ＋ 四处立即冲刷（退出/关预览/回后台/换书）→ writeAnnotations → annotations/<docId>.json
坐标系：存 PDF 用户单位（viewport scale:1），渲染只乘一个系数——与 dpr / fitWidth / 设备无关，任意倍率重绘不失真。
荧光笔不叠深不盖字：离屏层求并集 + canvas multiply + CSS mix-blend-mode:multiply 三层机制合起来。 回后台冲刷是独立于 JS 定时器的第二条保险（OEM 冻结后台 JS 时原生事件仍达）。

3返回键语义链 boot.mjs · Android 返回手势从最上层浮层开始消费，到根界面才「再按一次退出」

backButton 模态对话框（栈顶，先给拦截机会）→ 顶栏 ⋯ 菜单→ 阅读工具簇收起→ 取消摘录选词→ 退出标注（冲刷保存）→ 关预览（走按钮链路落进度）→ 收抽屉→ 根界面：2s 内再按一次才退出

每消费一层都清零「再按一次」计时——关掉浮层后 2 秒内误按不会杀掉应用。

5数据兼容不变量 移植的铁律——违反任何一条，整库互通即破

格式逐字段一致library.json 结构与桌面端完全一致；写入恒为「临时文件＋原子重命名」，半截文件永不出现在库根
事务串行＋已提交快照全部资料库变更共用 mutationQ：读只暴露 committedData；写失败回滚内存，删书在提交成功后才清文件与索引
SHA-256 / UUID 两端同值跨端去重与文档关联成立的基础；孤儿清扫只认严格 UUID 形状、库为空不清扫、只扫 files/ covers/
两条路径永不相交notes/ 只放 .md（Typora 互通）；平板专有数据放 annotations/、links/ 侧车——桌面端不识别即静默忽略
缺失 ≠ 故障存储适配器仅把明确的「文件不存在」当缺失；I/O 与权限故障上抛，绝不拿空库/空墨迹覆盖现存数据
平台差异优先上游化能写进桌面源码的（isMobile 分支 / 可选钩子 / 事件派发）就上游化，sync 补丁只留桌面装不下的（路径、专有 DOM、专有样式）——补丁从 44 处降到 14 处
