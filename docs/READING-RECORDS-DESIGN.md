# 方案书：书内记录（章节总结 + 列表内容优先）

> 状态：**已实施并真机验证**（2026-10-07 实施，检查单 a–j 全过）。
> 四项决策已由用户拍板：① 总结粒度 = 仅章（大纲顶级条目）；
> ② 无大纲的书功能自然缺席；③ 记录列表按页码升序；
> ④ 先落设计书、后批准实施。S3（TOC 📝 徽标）按约定暂缓，
> 视 S2 使用感受再定。
> 动因：自由笔记在平板端鸡肋（长文打字痛苦、桌面 Typora 场景不适配），
> 平板真正自然的节奏是「读完一章顺手收尾」+「读到哪句随手批注」。

## 1. 目标与非目标

**目标**

- 笔记面板从桌面继承的「文件列表」升级为「书内记录流」：**章节总结**
  （读完一章想到什么）与**摘录记录**（读到哪句想说什么）并列，按书的
  页序串成一条思考轨迹
- 跨章边界非阻断提醒：读完一章可选写总结，不打断阅读
- 列表内容优先：主行永远显示「你写的东西」，摘录文字/锚点等元数据点开
  查看器才出现
- 总结复用摘录记录全部基础设施（md 格式 / 侧车 / 查看器 / 编辑器 /
  删除链路），数据层零新增体系

**非目标（本期不做）**

- 定期复习提醒 / 间隔重复
- 「节」级（二级大纲）总结提示
- 删除或迁移既有自由笔记（桌面端仍在使用；保持可读可改）
- 原生层改动（无）

## 2. 关键决策一览

| # | 决策 | 选择 | 依据 |
|---|---|---|---|
| 1 | 总结的定位 | 复用摘录记录体系：总结 = 零摘录 + 章锚点的记录 | 一套生命周期（增删改查/缓存/删书清理）全复用；桌面 Typora 直接可读；互通不变量零破坏 |
| 2 | 提醒形态 | 非阻断小条（无遮罩、6 秒自动散、点正文即散） | 阅读流的打断感是此类功能的最大死因；弹窗模态否决 |
| 3 | 粒度 | 大纲**顶级条目**为章 | AI 书约 15 章粒度合适；二级 284 条会刷屏（拍板①） |
| 4 | 无大纲的书 | 功能自然缺席（不提示、手动入口隐藏） | 没有语义边界不硬造；页数边界是假的（拍板②） |
| 5 | 提示时机 | **向前**翻页跨过某章最后一页时；同一边界每次开书只提示一次（内存去重） | 翻回翻去不重复烦人；开书即干净 |
| 6 | 防刷屏 | 离开的章 <4 页不提示；标注/选词模式中、对话框开着不提示 | 密集小节与创作模式都不该被打扰 |
| 7 | 已总结的章 | 小条变「已总结 · 查看」；TOC 章条目带 📝 徽标（S3 可选） | 不逼着重写；回顾时一眼看到沉淀 |
| 8 | 列表主行 | 批注正文首行 →（无批注）摘录文字 →（总结）总结正文首行 | 用户关心「我当时写了什么」，不是「它从哪来」 |
| 9 | 列表排序 | 页码升序（记录锚点页）；自由笔记无锚点排尾部按时间 | 按书的阅读顺序串成思考轨迹（拍板③） |
| 10 | 时间戳文件名 | 界面不再显示，改为显示名/内容首行 | 文件名是机器产物，对人无意义（磁盘文件名不动，桌面不受影响） |

## 3. 不变量与约束（不可破）

1. **`.md` 互通不变量**：`notes/<docId>/` 只放 .md；`listNotes` 只认 .md。
   总结是 .md，桌面 Typora 打开即「【总结】头 + 正文」，可读可改。
2. **侧车移动端专有**：`links/<docId>.json` 桌面静默忽略；schema 升 v2
   向后兼容（v1 文件照读，无 summary 字段视作纯摘录记录）。
3. **摘录既有流程零改动**：选词/拖选/併入/追加/标记渲染全部原样。
4. **补丁体系**（实施修订，第四轮审查 Spec-c1 回填）：新补丁 ×2——preview.js
   目录构建处派发大纲（+1）与 notespanel.js 列表排序钩子（+1），38→40；
   其余全部落在 mobile-web 自有文件与运行时注入。
5. **提醒零持久化**：提示去重只在内存（每次开书重置），不写库不写侧车。

## 4. 概念模型

```
书内记录（notes/<docId>/*.md，按页升序串成思考轨迹）
├─ 摘录记录   md：> 【摘录】第 N 页 × k + 批注正文   侧车：excerpts[k]
├─ 章节总结   md：> 【总结】第 N 页 + 章名 + 总结正文  侧车：summary{page,chapter}
└─ 自由笔记   （桌面遗留，可读可改，列表尾部按时间）  侧车：无
```

三种记录同面板、同查看器、同编辑器、同删除链路；区别只在 md 头与侧车条目。

## 5. 章节总结设计

### 5.1 触发（跨章提醒小条）

```
        ╭──────────────────────────────────────────╮
        │ 读完《第 3 章 · 检索增强生成》  [✎ 写总结] [✕] │   ← 未总结
        │ 《第 3 章》已总结               [查看]  [✕] │   ← 已总结
        ╰──────────────────────────────────────────╯
```

- 位置：预览底栏上方居中（`bottom: 86px` 既有托盘槽位家族），浅底圆钮
  胶囊同 `.link-drag-bar` 视觉语言
- 检测：大纲顶级条目起始页构成边界；翻页后「上一页所在章 ≠ 当前页所在章
  且向前」即触发，只提示**离开的**那章（跳过多章也只提被读的那章）
- 守卫：标注中 / 选词中 / 对话框开着 / 小条已显示 → 不触发；
  离开的章 <4 页 → 不触发；同一边界本次开书已提示 → 不再提示
- 消散：6 秒无操作 / 继续翻页 / 点正文任意处；不做队列（同时只一条）

### 5.2 编辑与查看

- 编辑：复用记录编辑器（480px 紧凑款），标题自动 `总结 · <章名>`，
  正文空、保底 4 行；入口：小条「✎ 写总结」或面板「📝 本章总结」
- 同章已有总结 → 打开既有记录编辑（续写即修改），不建新文件
- 查看：复用记录查看器——chips 区显示**章锚点 chip**（`第 3 章 · P45`，
  点击跳章首），正文区即总结；总结记录隐藏「＋ 追加摘录」钮（无摘录可加）
- 删除：查看器 🗑 原链路（确认 → 删 .md + 侧车条目 → 列表刷新 →
  若 TOC 徽标已实施则同步去徽标）

### 5.3 手动入口（不等提醒也能写）

- 笔记面板头部「＋ 新建」旁运行时注入「📝 本章总结」图标钮（为当前页
  所在章写/续写；无大纲时隐藏——运行时注入，不动补丁）
- TOC 章条目 📝 徽标（S3 可选，观察器实现，不动补丁）

### 5.4 无大纲的书

小条永不出现；面板 📝 钮隐藏；既有摘录记录与自由笔记不受任何影响。

## 6. 列表内容优先

行结构两行式（替换现「文件名 + mtime + 第N页·摘录前24字」）：

| 记录类型 | 主行（内容优先） | 次行（弱化元数据） |
|---|---|---|
| 摘录（有批注） | 批注正文首行 | `🔗 · 第 8 页 · 2 小时前` |
| 摘录（无批注） | 摘录文字首行（即全部内容） | `🔗 · 第 3 页 · 时间` |
| 章节总结 | 总结正文首行 | `📝 · 第 3 章 · 时间` |
| 自由笔记 | 文件标题/首行 | `时间`（排序在尾部） |

- 主行省略号截断（沿用 note-link-row 修复后的 flex 两件套规范）
- 摘录具体文字、chips、跳转——点开查看器才出现（查看器现有结构即
  「chips + 正文」，正合适）
- 排序：锚点页升序（总结取 summary.page，摘录取 excerpts[0].page）；
  自由笔记无锚点排尾部按修改时间降序

## 7. 数据与文件格式

### 7.1 md 头扩展（link-md.mjs 纯函数，随单测）

```
> 【总结】第 45 页
> 第 3 章 · 检索增强生成

<总结正文……>
```

- 与【摘录】头同构（标记行 + 内容行 + 空行 + 正文），桌面可读
- `parseRecordMd` 返回扩展为 `{ ok, kind: 'excerpt'|'summary', body }`：
  见【总结】头 → summary；见【摘录】头 → excerpt；都没有 → 降级原样
- 向后兼容：旧文件不含【总结】头，解析路径逐字节不变

### 7.2 侧车 schema v2（links/<docId>.json）

```json
{ "version": 2, "records": {
  "2026-10-07 10.30.00.md": {
    "excerpts": [],
    "summary": { "page": 45, "chapter": "第 3 章 · 检索增强生成" }
  }
}}
```

- validate：v1/v2 均接受（读侧兼容）；条目需 `excerpts ≥ 1` **或**
  `summary` 存在；`summary.page` 整数 ≥1、`summary.chapter` 非空串
- 写侧一律产 v2；同章查重按 `summary.chapter` 精确匹配

## 9. 实施阶段

1. **S1 列表内容优先**（纯展示层）：md 解析扩展 → 行钩子改两行式 →
   页序排序。风险最低，独立真机验证

## 11. 风险与开放问题

| # | 风险 | 应对 |
|---|---|---|
| 1 | 大纲质量参差（章名空/超长/垃圾命名） | 小条与 chip 显示章名截断 24 字；空名回退「第 N 部分」 |
| 2 | 提示槽位与选词托盘同位（bottom 86px） | 守卫互斥（选词中不提示），物理上不同时存在 |
| 3 | 手改总结 md 破坏【总结】头 → 降级 | 既有降级路径原样：正文全保留、侧车锚点仍有效，行显示退为自由笔记样式 |
| 4 | 无大纲书后来补了大纲，旧总结按章名匹配不上 | 按章名精确匹配，匹配不上即视作新章（旧记录不丢，仍在列表） |
| 5 | 页序排序对「刚写完想看」不友好 | 行按住可考虑时间筛（开放问题，S1 真机用一周再定） |
